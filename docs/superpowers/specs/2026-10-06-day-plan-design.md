# 1日プラン 設計

- 日付: 2026-10-06（同日、「いくら得か」を前に出す形、エリアごとに複数のプランを出す形、予算超えと代替エリアを示す形、1日プランを「1日プラン提案」タブだけにする形に改訂）
- 担当: のむりん
- ブランチ: `feature/day-plan`（`feature/search` から分岐）

## 目的

検索結果の施設を組み合わせて、1日の過ごし方（1日プラン）として見せる。利用者が福利厚生の施設を「点」ではなく「1日の流れ」で検討でき、合わせて**いくら得か**が一目で分かるようにする。

## 決めたこと

| 項目               | 決定                                                                    |
| ------------------ | ----------------------------------------------------------------------- |
| 入口               | 検索結果の表示そのものを1日プランにする。専用の画面やメニューは作らない |
| 対象のタブ         | 「1日プラン提案」タブ（旧「文章で探す」）だけ。「施設を検索」タブ（旧「条件で探す」）は1日プランを組まず、施設の一覧だけを折りたたまずに出す |
| プランの数         | エリアごとに1つ。検索結果に出てくる順に最大3つ                          |
| 複数のプランの並べ方 | 縦に並べる。利用者が挙げたエリアが先、そのほかは代替案として後ろ。それぞれ検索結果で上位のエリアが上 |
| 予算を超えるとき   | お得額が最大のプランをそのまま選び、超える額をバッジと説明文で示して、お得感で納得してもらう |
| 挙げていないエリア | 「ご希望以外のエリアからの代替案」として示す                            |
| 施設一覧           | プランの下の折りたたみ「検索結果の施設一覧（N件）」に残す               |
| 空いた枠           | 同じエリアの周辺スポット（`spots`）で補う                               |
| 組み立て方         | 決まったルールで組む。AI は説明文だけを書く                             |
| 施設の選び方       | 枠ごとに、お得額（定価 − 福利厚生価格）が最大の施設                     |
| 料金プランの選び方 | 施設の料金プランのうち、お得額が最大のもの                              |

```
  午後  箱根園水族館          入場（大人1名）    定価 2,500円 → 1,800円     700円お得（28%）
  夜    箱根 芦ノ湖 はなをり  デラックス（2食付） 定価 48,000円 → 28,800円 19,200円お得（40%）
  福利厚生価格の合計：35,400円
  説明: …合計で21,600円お得です。
■ 1日プラン（熱海）                              合計のお得額
  …                                             18,700円お得
■ 1日プラン（沖縄）
  …
▶ 検索結果の施設一覧（N件）
▶ 使用した検索キーワード（N個）
```

- 見出しの右に、合計のお得額を大きな数字（`st.metric`）で出す。お得額が0のときは出さない
- 福利厚生の施設には、料金プラン名、取り消し線付きの定価、福利厚生価格、緑色の「〇〇円お得（〇%）」を並べる。お得額が0のときは「福利厚生 〇〇円」だけ
- 周辺スポットは名前と「周辺スポット」の表示だけ。`url` があれば名前をリンクにする
- 自由時間は「自由時間」の文字だけ
- 福利厚生価格の合計は、小さな注記として出す
- 福利厚生価格が予算（1つのプランあたり）を超える施設には、オレンジ色のバッジ「予算＋〇〇円」を付ける
- 利用者が挙げたエリア以外のプランは、見出しの横に青いバッジ「ご希望以外のエリアからの代替案」を付ける
- 検索結果が0件のときは、プランを出さず、これまでどおり「見つかりませんでした」と表示する
- 使用した検索キーワードは、いちばん下の折りたたみに入れる

## 組み立てのルール

入力は、検索結果の施設（並べ替え済み）と、プランのエリアの周辺スポット。

1. **エリア**: 検索結果に出てくるエリア（`area_id` があるもの）を、上位から重複なしで最大3つ取り、エリアごとに1つずつプランを組む。そのエリアの施設だけを使う。エリアのある施設がなければ、プランを出さない
   - AI が提案したキーワードにエリア名があれば、そのエリアを先に並べ、ほかのエリアは代替案（`alternative`）として後ろに並べる。キーワードを見るのは、「熱海は避けたい」のような否定を拾わないため（AI を使わない簡易な読み取りでは否定を読めない）
   - 代替のエリアを選ぶのは検索結果の順位で、AI ではない。AI は説明文だけを書く
2. **枠**: 次の4つを、この順に並べる

   | 枠   | 入れるもの            |
   | ---- | --------------------- |
   | 午前 | レジャー（`leisure`） |
   | 昼   | 食事（`meal`）        |
   | 午後 | レジャー（`leisure`） |
   | 夜   | 宿泊（`stay`）        |

3. **埋め方**: 枠ごとに、次の順で入れる。同じ場所は2回使わない
   1. 検索結果のうち、プランのエリアでカテゴリが合う施設の中から、**お得額が最大のもの**。同額なら検索結果で上位のもの
   2. 1がなければ、周辺スポットのうち `kind` が合うもの（読み込んだ順）
   3. どちらもなければ「自由時間」
4. **施設のお得額**: その施設の料金プランのうち、お得額（定価 − 福利厚生価格）が最大のプランのもの。同額なら福利厚生価格が安いプラン。プランがない施設は、お得額が最も小さいものとして扱う
5. **夜の枠**: 周辺スポットには宿泊がないため、宿泊の施設がなければ、夜の枠は出さずに「日帰り」と表示する
6. **合計**
   - お得額の合計: プランに入った福利厚生施設のお得額を足す
   - 福利厚生価格の合計: プランに入った福利厚生施設の福利厚生価格（お得額が最大のプランのもの）を足す。福利厚生施設が1つもなければ表示しない
   - 周辺スポットは価格がないので、どちらにも含めない
7. **予算**: 予算は「1つのプランあたりの上限」として扱う（検索の絞り込みと同じ）。予算を超えてもお得額が最大のプランを選び、超える額（`over_budget`）を記録する

一般サイト（楽天トラベルなど）との価格差は使わない。`market_prices` は空のため、定価との差だけで計算する。

## 説明文

- AI のキー（`secrets.toml` の `[llm]` の `api_key`）があれば、AI に2〜3文で書かせる
  - AI に渡すのは、プランの枠・場所の名前・紹介文・種類・定価と福利厚生価格とお得額、合計のお得額、利用者の入力（文章で探したときの文章、または条件）
  - 「プランに含まれる場所以外の施設や店の名前を出さないこと」「お得額があれば、合計でいくらお得かに触れること」と指示する
  - 予算を超える施設があれば、予算と超える額も渡し、「超える額とお得額の両方を示し、お得感の大きさを伝えること。お得額が超える額より小さいときは、そう正直に書くこと」と指示する
  - 代替案なら、「冒頭でそのことを断り、代わりに勧める理由を書くこと」と指示する
- キーがないとき、または AI の呼び出しが失敗したときは、決まった文の型で作る
  - 例: 「箱根で、午前は箱根小涌園ユネッサン、昼は箱根 自然薯の森 山薬、午後は箱根園水族館、夜は箱根 芦ノ湖 はなをりに泊まるプランです。合計で21,600円お得です。」
  - お得額の合計が0のときは、最後の「合計で〜お得です。」を付けない
  - 予算を超える施設があれば、最後に「夜の箱根 芦ノ湖 はなをりは予算を8,800円超えますが、定価より19,200円お得です。」を添える
  - 代替案なら、先頭に「ご希望のエリア以外からの代替案です。」を付ける
- AI の呼び出しは「探す」ボタンを押したときだけ行い、結果を `st.session_state` に保存する。画面の再実行では呼び直さない
- 説明文はプランごとに作るので、AI の呼び出しは1回の検索で最大3回になる

### 周辺スポットの読み込み

`spots` テーブルを読む処理（`spots.py`）は、なかりんさんの担当。できるまでは、`day_plan.py` に仮の関数 `_load_spots(tenant_id, area_id)` を1つだけ置き、`spots` テーブルを直接読む（そのエリアで、`tenant_id` が空（共通）または利用者のテナントのもの）。なかりんさんの関数ができたら、この関数の中身だけを差し替える。差し替える場所であることを、コメントで明記する。

## データの形（`day_plan.py`）

```python
@dataclass
class PlanItem:
    slot: str                  # "午前" / "昼" / "午後" / "夜"
    kind: str                  # "benefit"（福利厚生） / "spot"（周辺スポット） / "free"（自由時間）
    name: str
    category: str              # "leisure" / "meal" / "stay"
    description: str | None
    url: str | None            # 周辺スポットのリンク
    # 以下は福利厚生の施設だけ（お得額が最大の料金プランのもの）。周辺スポットと自由時間は None
    plan_name: str | None
    list_price: int | None     # 定価
    price: int | None          # 福利厚生価格
    saving: int | None         # お得額（定価 − 福利厚生価格）
    over_budget: int | None    # 予算を超える額。予算内か予算の指定がなければ None

    saving_rate -> int | None  # お得額の割合（%、四捨五入）。プロパティ

@dataclass
class DayPlan:
    area_id: str
    area_name: str
    items: list[PlanItem]
    day_trip: bool             # 宿泊がなく日帰りのとき True
    total_price: int | None    # 福利厚生価格の合計
    explanation: str = ""
    budget: int | None = None  # 1つのプランあたりの予算
    alternative: bool = False  # 利用者が挙げたエリア以外の代替案のとき True

    total_saving -> int        # お得額の合計。プロパティ
```

主な関数:

- `build_day_plan(menus, spots, area_name, area_id=None, budget=None) -> DayPlan | None`: 1つのエリアのプランを組む。`area_id` を省略すると最上位のエリア。DB も AI も使わない
- `plan_area_ids(menus, limit=3) -> list[str]`: プランを組むエリアを、検索結果に出てくる順に最大3つ返す
- `plan_area_id(menus) -> str | None`: 最上位のエリア
- `best_saving_plan(menu) -> Plan | None`: 施設の料金プランのうち、お得額が最大のもの
- `explain(plan, request_text) -> str`: 説明文。AI がなければ決まった文の型
- `make_day_plans(tenant_id, menus, request_text, budget=None, requested_area_names=()) -> list[DayPlan]`: 画面から呼ぶ入口。エリアごとに周辺スポットを読み、組み立て、説明を付ける。`requested_area_names` のエリアを先に並べ、ほかは代替案にする

## 失敗したときの扱い

| 状況                                        | 扱い                                     |
| ------------------------------------------- | ---------------------------------------- |
| 検索結果が0件、またはエリアのある施設がない | プランを出さない                         |
| 周辺スポットの読み込みに失敗                | 周辺スポットなしで組む（画面は止めない） |
| AI の呼び出しが失敗、または返答が空         | 決まった文の型の説明にする               |

## 確認方法

- `build_day_plan` は、DB を使わない仮のデータで、次のパターンを確かめる（`tests/test_day_plan.py`）
  - 検索結果だけで4つの枠が埋まる
  - 足りない枠を周辺スポットで補う
  - どちらもなく「自由時間」になる
  - 宿泊がなく日帰りになる
  - 結果が複数のエリアにまたがる（エリアごとに、そのエリアの施設だけでプランを組む）
  - プランを組むエリアは、検索結果に出てくる順に最大3つ
  - 予算を超える施設に、超える額が記録される。説明文に超える額とお得額が入る
  - 利用者が挙げたエリアが先に並び、ほかは代替案になる。挙げたエリアがなければ代替案にしない
  - 同じ場所が2回入らない
  - 枠ごとにお得額が最大の施設を選ぶ（同額なら検索結果で上位）
  - 施設の料金プランのうち、お得額が最大のものを使う
  - お得額の割合と、お得額の合計
- 説明文の決まった文の型を確かめる（AI は呼ばない。成功・失敗・空の返答は差し替えで再現する）
- 画面は Streamlit のテスト機能（AppTest）で、DB と AI を仮のものに差し替えて確かめる（リポジトリには入れない）
- 実際のデータでの確認は、`bts_app` の RLS ポリシーができてから行う

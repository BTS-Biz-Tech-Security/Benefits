# 1日プラン 設計

- 日付: 2026-10-06
- 担当: のむりん
- ブランチ: `feature/day-plan`（`feature/search` から分岐）

## 目的

検索結果の施設を組み合わせて、1日の過ごし方（1日プラン）として見せる。利用者が福利厚生の施設を「点」ではなく「1日の流れ」で検討できるようにする。

## 決めたこと

| 項目       | 決定                                                                    |
| ---------- | ----------------------------------------------------------------------- |
| 入口       | 検索結果の表示そのものを1日プランにする。専用の画面やメニューは作らない |
| 対象のタブ | 「文章で探す」「条件で探す」の両方                                      |
| プランの数 | 検索結果全体から1つ                                                     |
| 施設一覧   | プランの下の折りたたみ「検索結果の施設一覧（N件）」に残す               |
| 空いた枠   | 同じエリアの周辺スポット（`spots`）で補う                               |
| 組み立て方 | 決まったルールで組む。AI は説明文だけを書く                             |

## 画面

```
■ 1日プラン（箱根）
  午前  箱根彫刻の森美術館        周辺スポット
  昼    箱根 田むら銀かつ亭        周辺スポット
  午後  ○○レジャー施設            福利厚生 3,000円〜
  夜    箱根ホテル小涌園            福利厚生 30,000円〜
  福利厚生価格の合計: 33,000円〜
  説明: 午前は美術館でゆっくり過ごし、…
▶ 検索結果の施設一覧（12件）
```

- 枠ごとに、場所の名前と種類（「福利厚生」または「周辺スポット」）を表示する
- 福利厚生の施設には、最安の福利厚生価格を表示する
- 周辺スポットに `url` があれば、名前をリンクにする
- 検索結果が0件のときは、プランを出さず、これまでどおり「見つかりませんでした」と表示する

## 組み立てのルール

入力は、検索結果の施設（並べ替え済み）と、プランのエリアの周辺スポット。

1. **エリア**: 検索結果のうち、`area_id` がある最上位の施設のエリアにする。そのような施設がなければ、プランを出さない
2. **枠**: 次の4つを、この順に並べる

   | 枠   | 入れるもの            |
   | ---- | --------------------- |
   | 午前 | レジャー（`leisure`） |
   | 昼   | 食事（`meal`）        |
   | 午後 | レジャー（`leisure`） |
   | 夜   | 宿泊（`stay`）        |

3. **埋め方**: 枠ごとに、次の順で最初に見つかったものを入れる。同じ場所は2回使わない
   1. 検索結果のうち、プランのエリアでカテゴリが合う施設（検索結果の順位順）
   2. 周辺スポットのうち、`kind` が合うもの（読み込んだ順）
   3. どちらもなければ「自由時間」
4. **夜の枠**: 周辺スポットには宿泊がないため、宿泊の施設がなければ、夜の枠は出さずに「日帰り」と表示する
5. **合計**: プランに入った福利厚生施設の最安の福利厚生価格を足す。周辺スポットは価格がないので含めない。福利厚生施設が1つもなければ、合計は表示しない

## 説明文

- AI のキー（`secrets.toml` の `[llm]` の `api_key`）があれば、AI に2〜3文で書かせる
  - AI に渡すのは、プランの枠・場所の名前・紹介文・種類と、利用者の入力（文章で探したときの文章、または条件）
  - 「プランに含まれる場所以外の施設や店の名前を出さないこと」と指示する
- キーがないとき、または AI の呼び出しが失敗したときは、決まった文の型で作る
  - 例: 「箱根で、午前は箱根彫刻の森美術館、昼は箱根 田むら銀かつ亭、午後は○○、夜は箱根ホテル小涌園に泊まるプランです。」
- AI の呼び出しは「探す」「検索」ボタンを押したときだけ行い、結果を `st.session_state` に保存する。画面の再実行では呼び直さない

### 周辺スポットの読み込み

`spots` テーブルを読む処理（`spots.py`）は、なかりんさんの担当。できるまでは、`day_plan.py` に仮の関数 `_load_spots(tenant_id, area_id)` を1つだけ置き、`spots` テーブルを直接読む（そのエリアで、`tenant_id` が空（共通）または利用者のテナントのもの）。なかりんさんの関数ができたら、この関数の中身だけを差し替える。差し替える場所であることを、コメントで明記する。

## データの形（`day_plan.py`）

```python
@dataclass
class PlanItem:
    slot: str                  # "午前" / "昼" / "午後" / "夜"
    kind: str                  # "benefit"（福利厚生） / "spot"（周辺スポット） / "free"（自由時間）
    name: str
    category: str              # "leisure" / "meal" / "stay"
    description: str | None
    price: int | None          # 福利厚生の最安価格。周辺スポットと自由時間は None
    url: str | None            # 周辺スポットのリンク

@dataclass
class DayPlan:
    area_id: str
    area_name: str
    items: list[PlanItem]
    day_trip: bool             # 宿泊がなく日帰りのとき True
    total_price: int | None
    explanation: str = ""
```

主な関数:

- `build_day_plan(menus, spots, area_name) -> DayPlan | None`: 組み立て。DB も AI も使わない
- `plan_area_id(menus) -> str | None`: プランのエリアを決める
- `explain(plan, request_text) -> str`: 説明文。AI がなければ決まった文の型
- `make_day_plan(tenant_id, menus, request_text) -> DayPlan | None`: 画面から呼ぶ入口。エリアを決め、周辺スポットを読み、組み立て、説明を付ける

## 失敗したときの扱い

| 状況                                        | 扱い                                     |
| ------------------------------------------- | ---------------------------------------- |
| 検索結果が0件、またはエリアのある施設がない | プランを出さない                         |
| 周辺スポットの読み込みに失敗                | 周辺スポットなしで組む（画面は止めない） |
| AI の呼び出しが失敗、または返答が空         | 決まった文の型の説明にする               |

## 確認方法

- `build_day_plan` は、DB を使わない仮のデータで、次のパターンを確かめる
  - 検索結果だけで4つの枠が埋まる
  - 足りない枠を周辺スポットで補う
  - どちらもなく「自由時間」になる
  - 宿泊がなく日帰りになる
  - 結果が複数のエリアにまたがる（最上位のエリアだけを使う）
  - 同じ場所が2回入らない
- 説明文の決まった文の型を確かめる（AI は呼ばない）
- 画面は Streamlit のテスト機能（AppTest）で、DB と AI を仮のものに差し替えて確かめる
- 実際のデータでの確認は、`bts_app` の RLS ポリシーができてから行う
